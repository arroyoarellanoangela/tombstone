01

What I built

A pipeline of specialized agents — discovery, normalization, research, adviser lookup, verification, scoring — orchestrated by deterministic Python, ending in a filterable dashboard. No agent's output is trusted by default: every fact-bearing claim is re-checked by a downstream step before it is scored or published.

Why each hand-off exists

  • Discovery → Normalizer: discovery never judges what counts as a deal — it only returns candidates. Judgment (dedup, the acquisition definition, the time window) is centralized in one deterministic place, so it's testable and doesn't drift per-acquirer.
  • Research → Adviser Hunter: triggered only when the adviser field is empty. A different search strategy (advisory-side sources, not acquirer-side) is handed the problem specifically because the first approach didn't work — this is the clearest real delegation in the system, not parallel effort run by default.
  • Research → Verifier: the Verifier trusts nothing upstream. It re-fetches every cited source and can bounce a record back to Research, capped at two rounds to bound cost.
  • Verifier → Scorer: confidence is computed from Verifier outcomes, never asserted by an agent — an LLM-reported confidence number would itself be an unverified claim.
02

The core mechanism

The brief's grading line is explicit: a fabricated value is an automatic fail, a well-handled "undisclosed" is a pass. That line is encoded directly into the data model, not left as a prompt convention an agent might forget under pressure to fill a cell.

Every field is a Claim, not a string

// domain/models.py — Claim
{
  "field": "purchase_price",
  "status": "explicitly_undisclosed",
  "value": null,
  "source_url": "https://...",
  "verbatim_quote": "financial terms of
    the transaction were not disclosed",
  "source_language": "en",
  "verified": true
}

A validation hook rejects any agent output where a value has no accompanying verbatim quote — a structural gate, not a prompt instruction. The Verifier re-fetches the cited URL and checks the quote exists on the page by literal substring match: deterministic, and not gameable by a plausible-sounding hallucination, because a hallucinated quote does not exist on any real page.

Three field states, not two

StatusMeaning
verifiedA value was extracted and the Verifier confirmed the quote supports it.
explicitly_undisclosedThe source explicitly states the fact is not being disclosed — a positive, cited fact.
not_foundNo source addresses the field, or a claimed value failed verification.

Confidence is computed, never asserted

confidence = w1·source_tier + w2·corroboration_count
           + w3·verifier_pass_rate + w4·field_completeness

Weights and source tiers live in one config file, reviewable independent of any model's behavior.

03

Key decisions

DecisionWhy
Claude Agent SDK over LangGraphThe workflow is a bounded fan-out/fan-in with one conditional loop — not a complex stateful graph. Subagents, validation hooks and web search/fetch tools come built-in, billed against the client's own key, without an abstraction layer that needs its own justification.
Deterministic orchestrator for control flowBudget, cache keys, retries and run state have single correct answers. Delegating them to an LLM adds cost and non-determinism with no upside.
Verifier does literal quote-matching, not a second model opinionA second LLM call can hallucinate agreement with the first. A substring match against a freshly fetched page cannot.
Compliance allowlist enforced at the fetch layerA prompt instruction ("don't scrape LinkedIn") is a suggestion a model can ignore under pressure. A network-layer gate cannot be talked past.
Committed, documented snapshotLets the client judge output quality — the thing actually being graded — without spending their key or waiting on a live run first.
Quotes stored verbatim in source languageTranslating before extraction would break quote-grounding; the Verifier must match the actual page text, not a paraphrase.
04

What I cut

  • Mergermarket as a source. Paywalled, restrictive ToS. Documented as an omission rather than worked around.
  • All seven acquirers up front. The brief rewards depth over breadth directly — five acquirers, chosen to each stress a different part of the design (volume, Spanish-language, regulatory filings, edge-case deal definitions), rather than seven done flat.
  • Automatic conflict resolution. When two sources disagree on a value, the Verifier surfaces the conflict. Resolving it silently would reintroduce the exact fabrication risk the design exists to prevent.
  • Real-time/streaming monitoring. Acquisitions are announced, not ticking data. A scheduled or on-demand batch run covers the actual need without added infrastructure.
  • Translation, anywhere. Values and quotes from non-English sources (BSG) display exactly as extracted — in Spanish, tagged with source_language — with no translation step at all. Even translating just the extracted field would be a second place for meaning to drift from the verbatim quote it's grounded in.
05

Where it breaks

  • M&A adviser will often stay empty. Genuinely hard information even with lateral search — expected to be the sparsest field on the dashboard, by design rather than by failure.
  • Single-source claims. Some legitimate facts, especially from smaller acquirers, only ever appear once. Marked with lower confidence, not discarded.
  • Site structure changes. An acquirer reworking their press room mid-project degrades that Discovery instance to zero new candidates rather than failing loudly — mitigated by a minimum-yield check per run, not solved outright.
  • Verifier false negatives. Legitimate paraphrased reporting that isn't a literal substring of any page is marked not_found rather than verified — a deliberate bias toward under-claiming over a looser match that risks a false positive.
  • Cost ceiling. The Adviser Hunter and the two-round Verifier loop are the main cost drivers, both hard-capped — under budget pressure the system yields more not_found fields rather than exceeding spend.
06

Repository structure

One private repository. The root itself is the backend — src/ is flat, not a nested src/tombstone/ package, matching the convention across the author's other production repos: not pip-installed, imported directly as from src.domain.... frontend/ is the one subfolder outside src/. domain/ holds pure logic with no framework imports, so the Claim model and scoring rubric are testable in isolation from FastAPI, the Agent SDK, or any network call.

src/domain/
The one directory every other layer depends on and that depends on nothing itself. If the Claim schema or scoring rubric needs to change, it changes here, with unit tests that don't spin up an agent or hit a network.
sources/
Config, not code — every acquirer's scope (allowed domains, language, source type) and the ToS gate live here as data, so extending coverage or auditing what's off-limits never requires reading Python. Deliberately separate from data/: sources/ is what Discovery is told to look at, data/ is what it found.
sources/profiles/
One acquirer, one file — language, allowed domains, source type. Adding an acquirer (Everfield, Valsoft) is a new profile, not a code change to Discovery.
sources/allowlist.yaml
Read by utils/fetch.py before any request leaves the process. LinkedIn and Mergermarket are listed here as allowed: false with a reason — the omission is data, not a comment.
data/
Only snapshot_*.json and omissions.json are committed. cache.db is local-only — it exists to make repeat runs cheap against the client's key, not to be shared state.
src/api/
Thin by design: serves the snapshot and can trigger a fresh run; it holds no business logic that isn't already in domain/ or agents/.

Deployment: two modes, same codebase

The full stack (docker compose up) is what runs live, locally, for the walkthrough call. What's ever reachable from a public link is different on purpose: a static build of frontend/ reading data/snapshot_*.json directly, no API involved. A publicly reachable API that could trigger the pipeline would let anyone who finds the link spend the client's prepaid credits — the static deployment removes that surface entirely rather than trying to secure it. Planned host: Vercel or Netlify's free tier, on a subdomain of the author's own domain. This is the last item on the build list, a bonus on top of the required deliverable, not a substitute for it — docker compose up alone already satisfies "runnable by us."
